# 12 — Observability Architecture

| Pillar                    | Phase 00 implementation                                                                                                                                                                        | Production strategy                                                                                                                               |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Structured logs           | pino JSON via nestjs-pino; redaction of auth/cookie/token fields; req/res serializers limited to id, method, url, UA, status; health probes not auto-logged; pretty output only in development | Stdout → awslogs driver → CloudWatch Logs group `/quest/<env>/api` (retention 14/30 d); Logs Insights queries by `correlationId`                  |
| Request / correlation ids | `RequestContextMiddleware` (AsyncLocalStorage) sets `x-request-id` + `x-correlation-id`; ids in every log line and event envelope                                                              | CloudFront/ALB pass `x-correlation-id` through; clients (api-client) always send one                                                              |
| Health / readiness        | `/health` (process), `/ready` (Postgres + Redis critical, storage degraded) with safe detail codes                                                                                             | ECS container healthcheck → `/health`; ALB target group → `/ready`                                                                                |
| Metrics                   | `MetricsPort` (`increment/histogram/gauge`) with `NoopMetrics`; naming `quest.<context>.<metric>` low-cardinality                                                                              | OpenTelemetry meter → CloudWatch EMF or OTLP collector sidecar; CloudWatch 5xx metric filter + alarms exist in Terraform                          |
| Tracing                   | `getTracer()` seam over `@opentelemetry/api` (no-op until an SDK is registered)                                                                                                                | `OTEL_ENABLED=true` + NodeSDK preload with auto-instrumentations (http, pg, ioredis, nest) exporting OTLP to an ADOT collector → X-Ray/CloudWatch |
| Error monitoring          | 5xx logged with stack + correlation id; envelope never leaks internals                                                                                                                         | CloudWatch alarm → SNS topic (`observability` module); error-tracking vendor optional later                                                       |
| Audit logs                | Safety assessments and AI invocation records are append-only data, not log lines                                                                                                               | Dedicated tables with retention; moderator actions logged with actor id                                                                           |
| AI telemetry              | `AiInvocationRecord` carries provider, model, latency, tokens, estimated cost, outcome, fallback                                                                                               | Sink to PostgreSQL + metrics per task                                                                                                             |

Principles: never log request bodies by default; never log precise location or evidence keys with
user identifiers; attributes on metrics are low-cardinality (no user ids).
